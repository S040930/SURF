题目：4.13、5.7 条件：NM / CRM / ARM 模型：DeepSeek · Doubao 历史：h=10（探测）· h=20（终点） 状态：completed · 2026-08-20 17:07
本报告是对已完成技术试点 锁定的 technical-only 报告（core=null）的事后探索性解封：样本只有 2 道试点题，所有读数为描述性观察，不构成正式 RQ1 / RQ2 结论，也不能据此推广到正式题、其他模型或总体准确率。统计口径与附录一致。

一、核心结论（一页速览）

  • 运行健康：1488 次 attempts，0 次调用级失败，0 次记忆约束违规；但 attempt 层面约 31% 需要重试（241 uncertain、217 invalid_response、7 transport_error），p95 延迟 300.1s 触及 300s 超时上限——正式运行前需关注尾部超时与无效响应重试率。
  • 题目难度差异明显：h=20 时题目 4.13 的 NAE（0.37–0.57）远高于 5.7（0.06–0.09）。4.13 是"难题"，5.7 误差已经很低。
  • 记忆未改善误差（RQ2 描述性）：四格 memory mean − NM 中三格为正（+0.025 ~ +0.113），仅 Doubao×5.7 为 −0.013；题目宏平均 +0.038。即在本试点中，外部记忆并未降低评分误差，在难题 4.13 上反而更差（+0.070 合并）。
  • ARM vs CRM 无一致方向（RQ1 描述性）：四格 ARM−CRM 正负交错（+0.007 / −0.017 / −0.062 / +0.020），宏平均 −0.013，主要由 Doubao×4.13 单个格子驱动；在 n=2 题、无置信区间下视为噪声。
  • 更多历史未降误差：h=10 → h=20，12 格中 8 格误差上升（总体均值 0.275 → 0.288）；4.13 上全部 6 格随历史变差。学习曲线呈"平台或微升"，而非下降。

七、结论与解释边界

试点层面的结论（描述性，仅限这 2 道题）

  • 管线工程上稳健：0 调用级失败、0 约束违规、成本可控，具备进入正式 8 题运行的可行性。
  • 本试点未观察到记忆带来的收益：记忆均值−NM 宏平均 +0.038；在难题 4.13 上记忆反而更差。ARM−CRM 无一致方向，宏平均 −0.013 由单格驱动，视为噪声。
  • 题目间异质性极大（4.13 vs 5.7 的 NAE 差约 6 倍），正式分析必须坚持"题目等权 + 题目级宏平均"的口径，避免被难题主导。

为什么这不能当作正式结论

  • 只有 n=2 题，无 10,000 次 bootstrap 区间，无法区分"真效应"与"题目/轨迹噪声"。
  • 试点协议明确不展示方向性效果；本报告是对锁定 technical-only 报告（core=null）的事后解封，不改变其状态。
  • h=10 探测与 h=20 终点测量口径不同，学习曲线差值混入了重复评分降噪。
  • 四格内部正负交错（如 Doubao 4.13 与 5.7 方向相反）本身就是"无一致模式"的直接证据。

对正式运行的提示

  • 尾部延迟：p95 300.1s 顶到超时上限，正式 11,520 次调用需按 p95 而非 p50 规划并发与时间窗，并确认 provider 的 rate-limit 与超时重试策略。
  • 无效响应率 ~15%：集中在 JSON schema，正式前可复核解析器与 prompt 稳定性，但注意协议禁止在正式 run 中"修 prompt"——任何修改都需先过 48-call 开发校验套件。
  • 学习曲线探测点（h=20/40）同样存在测量口径差异，正式报告解释时应与本次一致地注明。
