# DREsS 三轴效度：analysis_v2 偏差纠正与启动约束

## 已完成的非破坏性修正

`outputs/exp_dress_new_formal/analysis_v2/` 由锁定的无正文 `results.csv` 重新计算。
它用 `(model, input_sha256)` 把同一篇作文的主评分和第二次独立评分配对；旧 v1 报告的复测段
错误地再次将第二次模型输出与档案专家标签比较。原始 `report.json`、`manifest.json` 和导出文件
没有被修改。

因此，analysis_v2 中约 0.62–0.71 的 Organization QWK 是**模型自一致性**，而不是与专家标签
的一致性；同维度的模型—专家 QWK 约为 0.27–0.30。稳定不等于正确。

所有 QWK、MAE 和 signed bias 都以 10,000 次、固定种子的非参数 bootstrap 提供区间。旧的
`log(word_count) + prompt` 结果仅可称为“有监督 prompt+length 基线”，不是零样本 LLM 的公平
竞争基线；若继续使用，须改为 prompt-held-out 诊断。

## v2 确认性协议（尚未调用模型）

新的冻结项目必须是 `2 模型 × 3 量表条件` 完全交叉设计：C0 最小条件、C1 DREsS Table 2
档案量表、C2 已冻结完整锚点量表。正式样本为 360 篇（五个综合分层各 72），复测为 60 篇
（各层 12）；技术试点为 15 篇（各层 3），且试点输入不得进入 CASE 对齐复现池。每个模型为
Luna 与 Terra、`medium / standard / 120s`，不得根据中间结果替换。

确认性池排除任一档案维度为 0.5 的记录；评分契约固定为 1.0–5.0、步长 0.5。Organization 是
唯一确认性维度，主要对比 C2−C1；Content 次要，Language 因既有 CASE 扰动混杂仅探索性。

正式调度前必须满足以下验收点：

- 每次调用永久记录 `condition_key`、量表哈希与确定性 `dispatch_rank`；唯一键覆盖模型、输入、条件与运行序号。
- 主评分 2,160 次全部结束后，才允许开始 360 次复测；三条件共同重新评分。
- CASE 对齐复现另取 12 个未进入试点的 Organization base，每 base 17 个槽位；它只检查跨实验配置对齐。
- 报告按条件保留配对键且不导出作文正文；模型比较采用保持作文联合配对的 10,000 次分层 bootstrap，另给 prompt-cluster 稳健性分析。
- 技术试点 90/90 成功、运行快照无漂移、正式结果在解封前密封，且同一数据库状态生成字节一致报告。

总量约 3,018 次调用；串行预算约 9–13 小时，CPU、内存和磁盘各低于 1 GB。模型额度和服务漂移
是主要风险，因此创建/启动该项目必须由操作员显式确认，不能由分析修复脚本隐式触发。
