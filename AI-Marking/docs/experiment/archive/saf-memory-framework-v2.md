# SAF 2.0 独立记忆框架研究设计（v2，已退役）

> 本文件保留已终止的双模型 v2 冻结协议，供旧项目 `66b95855-1555-4581-ae6b-b736bb8c1def` 审计使用；不得与 v3 数据混合。

协议 ID：`saf-memory-framework-v2`。

本研究与 r20/r21/r23 使用不同的路由、`ms_*` 数据表、研究目录、配置快照、记忆库和报告。旧实验不迁移、不覆盖，也不继承旧实验的题目角色、split map、轨迹或分析函数。

## 研究问题

在同一批历史人工批改材料下，普通完整案例检索、Mem0、A-MEM 是否相对无记忆降低新回答评分的归一化绝对误差；去掉人工文字反馈后，误差与资源开销如何变化。

正式研究固定为六道题，每题 40 条训练记录、10 条 `unseen_answers` 测试记录；每个训练与测试答案各评分一次。Luna 与 Terra 各自独立构建记忆。每题训练池生成三种确定性历史顺序，训练完成后才开始测试，不产生中期评分或学习曲线。

基础 wave 固定为：无记忆、确定性检索/完整、Mem0/完整、A-MEM/完整；无反馈的三条条件作为独立可选 wave。记忆材料只包含题目、学生答案、人工分数，以及完整条件下的人工反馈；参考答案和 `verification_feedback` 均不进入记忆。评分请求仍使用参考答案作为评分标准；测试人工分、人工反馈和 `verification_feedback` 均不进入模型请求。

## 数据边界

`app/experiment/memory_study/dataset.py` 直接读取固定 SAF 2.0 归档并核对归档 SHA-256。它重新执行 XML 解析、重复/近重复/跨 split 与身份关联排除，然后以 v2 协议对题目 ID 做确定性哈希排序：先选满足 40/10 的六道正式题，再从剩余互斥题目选两道开发题和两道试点题。满分仅从历史训练材料确定。

持久化的 `ms_records` 是受限本地数据；公开 API 和默认导出只暴露答案 ID、题目 ID、分数/差值、哈希、token 和资源账本，不暴露学生正文、完整 prompt、密钥或验证标签。

## 记忆与调用

所有框架通过五个操作适配：`ingest`、`snapshot`、`restore`、`retrieve`、`inspect`。普通检索、Mem0 和 A-MEM 统一使用同一个 OpenAI-compatible API embedding 模型、端点和固定版本；普通检索执行余弦相似度和完整案例 top-20。开发/试点在项目创建时生成确定性的独立检索快照，不创建模型写入调用。官方 Mem0 固定到 `c7ee362aff94a369af70f13f2b4f853f6793ff4c`，只通过 `Memory.from_config()`、`add()` 和 `search()`；A-MEM 固定到 `f303dfc71e07bdc787f4bc135d4cea328ae30e99`，只通过 `AgenticMemorySystem.add_note()` 和 `search()`。

每个模型、题目、条件和历史顺序拥有独立 memory store。训练写入成功后原子提交数据库快照和文件快照；测试只读取最终快照。每个 Codex 调用都有独立临时目录、attempt 和 token 账本，失败差值为空，人工重试不新增逻辑重复。

## 分析与规模

主指标为：先对每题单次评分的归一化绝对误差取平均，再对六题等权平均。Mem0/A-MEM 相对普通检索的差值按模型配对计算。分析关闭 bootstrap、重采样、显著性检验和总体推断置信区间。

正式基础反馈 wave 为 `6 × 2 × 3 × 4 × (40+10) = 7,200` 次评分，三个有记忆条件写入为 `6 × 2 × 3 × 3 × 40 = 4,320`。无反馈条件作为独立 wave 按需追加。六题独立分片共享 Luna/Terra 各四个固定槽（最多 8），每个题目×模型×memory store×feedback wave 严格串行，槽间可并行。
