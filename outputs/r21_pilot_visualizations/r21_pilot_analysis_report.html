一、核心结论（一页速览）

关键读数（h=20 终点，n=15 个 endpoint×trajectory 单元/格）

  • 运行健康：680 次 attempts、0 次调用级失败、0 次失败记录；延迟 p50 18.3s、p95 39.6s，全部远低于 600s 超时上限——较 r20 的尾部超时问题明显改善。
  • 题目难度差异仍在：h=20 时 4.13 的 NAE（0.46–0.51）远高于 5.7（0.07–0.10）。4.13 仍是"难题"。
  • 记忆未改善误差（RQ2 描述性）：两格 memory mean − NM 均为正（4.13 上 +0.023，5.7 上 +0.012），题目宏平均 +0.018。即本试点中外部记忆并未降低评分误差。
  • ARM vs CRM 无一致信号（RQ1 描述性）：两格 ARM−CRM 均为正（+0.040 / +0.019），宏平均 +0.030（CRM 略优）；但 n=2 题、无置信区间，视为噪声。
  • 更多历史未降误差：h=10 → h=20，6 格中 4 格误差上升，总体均值 0.280 → 0.280（基本平台）。

七、结论与解释边界

试点层面的结论（描述性，仅限这 2 道题、单模型）

  • 管线工程上稳健：0 调用级失败、0 失败记录、延迟远低于超时上限，具备进入正式 8 题运行的可行性。
  • 本试点未观察到记忆带来的收益：记忆均值−NM 宏平均 +0.018；ARM−CRM 宏平均 +0.030（CRM 略优），均无一致的方向性证据。
  • 题目间异质性仍然极大（4.13 vs 5.7 的 NAE 差约 5–6 倍），正式分析必须坚持"题目等权 + 题目级宏平均"的口径。

为什么这不能当作正式结论

  • 只有 n=2 题、单模型，无 10,000 次 bootstrap 区间，无法区分"真效应"与"题目/轨迹噪声"。
  • 试点协议明确不展示方向性效果；本报告是对锁定 technical-only 报告（core=null）的事后解封，不改变其状态。
  • h=10 探测与 h=20 终点测量口径不同，学习曲线差值混入了重复评分降噪。
  • 模型为单个 operator 选定的 Codex CLI 配置，不代表所有 LLM 或供应商。

对正式运行的提示

  • 延迟健康：p95 39.6s、max 75.5s，远低于 600s 超时——Codex CLI 路线的尾部延迟较 r20 的 API 路线明显更稳，可按 p95 规划并发。
  • 记忆 token 近似偏大：如本报告近似口径所示，建议正式前用 o200k 真实计数复核快照可见 token，避免接近 720 上限。
  • 单模型限制：正式协议若保持单模型，模型级结论范围有限；如需对模型总体作推断，应按协议补充第二个固定模型配置。
